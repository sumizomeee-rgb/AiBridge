## 分阶段开发计划 (v2 — 经苏格拉底自检修订)

### Phase 0: 协议设计与接口约定
- 定义 Server <-> Extension WebSocket 消息 JSON Schema（任务下发、Chunk 回传、错误回传、心跳）
- 定义统一错误格式（错误码 + 错误消息），覆盖：未登录、DOM 超时、Tab 不存在等场景
- 定义 OpenAI `/v1/chat/completions` 和 Anthropic `/v1/messages` 两种外部接口的请求/响应映射
- 产出：`03_通信协议.md` 存入施工记录

### Phase 1: Local Server 构建
- 初始化 Node.js 项目 (`server/`)
- 实现 Express HTTP 服务：
  - `POST /v1/chat/completions` (OpenAI 兼容)
  - `POST /v1/messages` (Anthropic 兼容)
- 实现 WebSocket Server (同端口 1337 复用)
- 实现请求暂存机制 (`activeTasks` Map)
- 实现 SSE 流式响应返回
- 实现错误响应（按 Phase 0 定义的错误格式）
- CORS 全局配置
- 用 curl 手动验证接口骨架

### Phase 2: Extension 骨架与通信
- 初始化 Vite + @crxjs/vite-plugin 项目 (`extension/`)
- 编写 `manifest.json` (MV3)
- Background Service Worker:
  - WebSocket 客户端连接 + 断线重连
  - **MV3 Keep-alive 方案**（Offscreen API / 定时心跳，防止 Service Worker 30s 休眠）
  - 任务队列：同一 Tab 的任务串行执行，避免 DOM 操作冲突
- 基础 Popup UI: 连接状态指示灯
- 验证 Server <-> Extension WebSocket 双向通信（含心跳）

### Phase 3: 路由控制与 Tab 管理
- Popup UI: 路由模式切换 (Auto / Override)
- Popup UI: Override 目标选择 (ChatGPT / 豆包 / Claude 等)
- `chrome.storage.local` 配置读写与同步
- Background: 根据路由策略查找/新建/激活目标 Tab
- Background: 将任务通过 `chrome.tabs.sendMessage` 派发给 Content Script

### Phase 4: Content Script 核心适配器
- 定义适配器接口 (`newChat` / `sendMessage` / `observeResponse` / `reportError`)
- 以 ChatGPT 为首个目标实现适配器:
  - 点击 New Chat
  - React 兼容的模拟输入 (dispatchEvent)
  - MutationObserver 增量文本抓取
  - 异常检测（未登录提示、速率限制等）并通过错误链路回传
- 增量 Chunk 原路返回: Content -> Background -> WS -> Server -> SSE

### Phase 5: 集成联调与打包交付
- 端到端全链路验证（Agent -> Server -> Extension -> AI页面 -> 流式返回）
- Chrome 插件打包为 `.crx` / 发布就绪的 zip
- Server 通过 `pkg` 打包为独立 `.exe`
- 编写最终使用说明

## 开发优先级与依赖关系

```
Phase 0 (协议设计)
    │
    ├──→ Phase 1 (Server) ──┐
    │                        ├──→ Phase 5 (集成联调与打包)
    └──→ Phase 2 (Extension骨架) ──→ Phase 3 (路由) ──→ Phase 4 (Content Script) ──┘
```

- Phase 0 完成后，Phase 1 和 Phase 2 可以并行开发
- Phase 5 是 Server + Extension 的统一交付节点
- 每个 Phase 完成后在本目录下记录施工日志
